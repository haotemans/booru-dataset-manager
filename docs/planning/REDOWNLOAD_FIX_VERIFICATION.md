# Original redownload feedback fix — 2026-10-25

Review found that the review/similarity shell returned before drawing notifications, the download button had no dedicated status popup, and asynchronous failures populated a different error field from the editor. Result polling also depended on rendering a media review. The backend rejected every saved edit record as though it were an unfinished save.

The shell now always polls and renders download feedback. A persistent popup displays progress, blockers, failures and success. While it is open, review controls and shortcuts are disabled; Escape dismisses only a completed result. A saved edit is permitted, an actual pending repair journal is rejected, and successful downloads reset edit dimensions while retaining the current-file backup and source provenance.

Validation uses temporary catalogs and synthetic images. Six added regressions cover actual mouse clicks in both editor tabs, popup layering and notifications, Escape and review shortcuts, worker failures/disconnection, result delivery after review closes, restored crop/inpainting originals and backups, and invalid-source preservation. All six passed.
