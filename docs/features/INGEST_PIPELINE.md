# Ingestion pipeline

Current code now implements Danbooru static PNG/JPEG/WebP discovery, bounded streaming, actual format/animation/dimension validation, MD5/SHA-256, SQLite import journal, provenance and background analysis. See [delivery evidence](../planning/WORKFLOW_DELIVERY.md). The earlier implementation paragraph below is historical.

Default media scope: confirmed static images only. Skip every GIF (including a single-frame GIF), video (WebM, MP4 and other video formats), and other animated images such as APNG or animated WebP/AVIF. Apply this type gate independently of the dimension gate. Do not substitute a static thumbnail, first frame or converted still for an excluded original.

Classify original media from provider format/MIME and animation metadata before downloading. Unknown or contradictory type information is skipped as `media_type_unknown`; do not assume an image MIME type proves that the original is static. After download, validate the actual file type and animation/frame metadata again before import, hashing or commit. If a downloaded candidate is GIF, video or animated, discard its temporary file and record the type skip. Filtered items are not failed downloads, are not retried and do not count toward eligible/downloaded-image targets. Source Tag API totals remain the provider's unfiltered count.

Current implementation: `DownloadMediaPolicy::StaticImagesOnly` is the default in app configuration and desktop preferences, including preferences written before this field existed. The download path filters provider metadata and decodes actual PNG/JPEG/WebP bytes to reject format mismatches and animation before import.

Minimum original dimensions: the default original short-side threshold is 800 px (width >= 800 AND height >= 800). System Settings → Download scope exposes a saved minimum short side, editable from 1–16384 px with Restore default and Save download settings. Values below 800 are permitted; 16384 is the existing decoder side limit. The saved value applies to newly created jobs; running/resumed jobs retain their serialized threshold. Both provider-metadata filtering and decoded-file validation use that job threshold. Imported media and import-journal records retain the threshold for crash recovery, so lowering it does not break recovery on restart. Legacy preferences/jobs/media without the field default to 800; changing settings does not delete or re-filter existing library items. Prefer original metadata dimensions; thumbnail dimensions are not a substitute. Unknown dimensions are skipped as resolution_unknown by default unless the user explicitly overrides. Verify actual dimensions after download.

Import flow: DISCOVERED → VALIDATING → HASHING → EXACT_DEDUP_CHECK → COMMITTED. Commit the valid media and provenance independently of DINOv3 availability. After commit, enqueue a separate analysis work unit: PENDING_EMBEDDING → DINO_EMBEDDING → SIMILARITY_SEARCH → MATCHED_IDENTITY | NEW_IDENTITY | NEEDS_REVIEW. If the model/runtime is unavailable, keep analysis pending with an actionable reason; do not roll back or block the imported media.

Download to temporary storage, validate actual image/dimensions, compute MD5 and check database uniqueness, compute SHA-256 integrity hash, move to managed library, commit metadata transaction, and reconcile interrupted operations at startup. No partial final file or dangling database row should survive recovery.

Planned providers: Danbooru, Gelbooru, Pixiv, X/Twitter, E-Hentai. Browser login does not automatically grant app access to browser cookies/session. Use supported site-specific authentication only; do not bypass CAPTCHA, paywalls, access controls or provider policies. Adapters need rate limits, retry/backoff, cancellation and auditable errors.


## Decoupled visual analysis

DINOv3 embedding and similarity analysis is queued by default after successful media commit, but is not part of the ingestion transaction's success condition. Analysis queue state, attempts, model/preprocessing version, errors and results are persisted separately. Users can start batch analysis for existing library items and re-run analysis after selecting a new model or preprocessing version. New analysis must preserve prior results and human-confirmed group/representative decisions in history; it must not silently replace them. Show import progress and analysis progress separately.

Desktop dispatch runs download and dedup concurrently. Starting/resuming a download enables the persistent analysis queue; each committed image can be analyzed while later originals are downloading. A single dedup worker consumes oldest-first batches of at most 64 media, compares against the compatible library index, then drains further batches after download completion. Network transfer, image validation/thumbnail preparation and model inference run outside the shared media-mutation lock. Catalog connections in the same desktop process coordinate promotion/commit/local-tag completion and dedup deletion with that lock. Immediate write transactions and bounded ingestion busy retries remain in place. Independent processes are not coordinated by this in-process lock.

Pausing processing disables automatic continuation for that session even if further imports arrive. A new download, **继续任务** on an automatic dedup job, or **继续自动去重** explicitly enables it again. Restart never auto-resumes network or analysis jobs. Missing-model items persist as `needs_model`; they are excluded from automatic batches while weights are absent, and failed items require manual retry. Analysis failure does not cancel downloads or discard committed media.

Tag optimization, caption generation, alias/character discovery and metadata refresh are manually triggered. Download completion never starts these operations. Import still preserves raw source tags and materializes deterministic local normalization using saved rules; recovery fills missing local artifacts without replacing current edited/AI text. AI, metadata and export workflows wait until download/dedup processing has finished or been paused, and block a new download while active.
