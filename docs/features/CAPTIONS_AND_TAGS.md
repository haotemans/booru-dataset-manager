# Captions and tags

Applied character relations stay effective without repeat review. The Character page shows only unresolved ambiguous relations; optional applied-rule inspection, source refresh, offline retry and manual edits are in System Settings → Character relations → Character relation settings. Completed automatic work consumes no Character-page space.

Implemented: immutable raw sidecars, independent tags/caption artifacts, local protected-name merge, confirmed character hierarchy with coexisting variants preserved, exact-term protection, manually triggered background metadata discovery and reviewed/optimized artifact preservation. Download/dedup is an automatic pipeline; AI tags/captions and online alias/character discovery run only after explicit user action. Imports still materialize deterministic local tags using saved rules. Cached lookups and manually rejected character relationships survive restarts. The full classification/approved mapping vocabulary below is still being built; see [delivery and remaining limits](../planning/WORKFLOW_DELIVERY.md).

Three independent UTF-8 sidecars per basename: image.raw_tags.txt (source provenance, preserve order/text, never AI-rewrite); image.tags.txt (meaning-preserving normalized tags); image.txt (factual natural-language training caption). Each artifact has its own version, hash, source/model/prompt config, state, error and review status. Unselected targets are untouched; a failed target does not roll back successful targets; reviewed content is never silently overwritten.

Review tabs are ordered 原始标签 / 优化标签 / 自然语言 and initially select raw source text. Automatic import formatting (`local-normalization-v1`) is not an optimization result and does not populate the optimized tab. Generated tabs show only nonempty, provenance-bearing results in `complete` or `needs_review`; pending human confirmation remains visible. Without a target-specific optimization job or result, show 尚未优化标签 / 尚未优化自然语言 and disable Copy; no text-confirmation action is offered. Existing jobs without results show their running/paused/failure status. Reading or switching tabs never starts optimization. Tags and natural language remain independent; raw source storage preserves source order, whitespace and underscores. Review display and Copy suppress a redundant base character only when its confirmed specific variant is also present; a lone base survives. The same filter applies to optimized-tag display and tag exports (including previously reviewed artifacts), while stored source text and reviewed artifacts remain unchanged. Captions are not filtered.

Preset 默认数据集优化: artist enabled, local formatter emits @artist name and never sends artist name to AI; character enabled, canonical library name in plain format and never AI-rewritten; tags enabled, AI processes ordinary tags only and protected names are merged locally; caption enabled, factual training description. Artist-only must not call AI. Caption-only must not change tags/artist/character; tags-only must not change caption.

Classify artist, character, work-specific, anatomical/technical, visual feature, ordinary descriptive, and ambiguous/conflicting terms. Strong protection forbids deletion/generalization; conditional mapping requires reviewed canonical mapping; ordinary normalization permits meaning-preserving changes only. Unknown terms stay unchanged and require review. Never infer domain-term definitions without trusted evidence or human confirmation. Use exact normalized matching and explicit aliases, not naive substring matching.

Validate protected-term coverage, approved mappings, unauthorized replacements, unsupported additions, raw-source immutability and association stability. AI semantic judgement is supplemental, not the sole approval criterion. Write via temp file and atomic replace where supported; preserve prior valid versions.

## Dual prompts and one-image/one-TXT AI labeling (feature branch)

API profiles now store independent, editable natural-language and Tag optimization system prompts, with separate restore-default actions. Existing saved profiles use safe defaults for these new fields. The strict JSON envelope, IDs, protected-name handling and response parser remain mandatory regardless of user prompt customization.

When **send images + paired TXT** is enabled, both optimization targets use vision. Each individual request carries exactly one managed image (in-memory JPEG preview) and the UTF-8 same-basename `.txt` content as `paired_txt`, alongside ordinary-source-tag reference data. Requests are still linked to stable media IDs. Missing, malformed or oversized paired TXT prevents that image from being uploaded and marks the ID for recovery. A blank TXT is permitted because newly imported media can have an empty caption sidecar. Files are read at dispatch, not copied into logs.

Image-enabled Tag mode may introduce visible descriptive tags or fix ordinary-tag inaccuracies. Such output always requires human review. The text-only Tag mode retains the original strict meaning-preservation/set-equality protection. Artist and character identities stay protected and are merged locally. Original `.raw_tags.txt` is never AI-rewritten. The existing target artifact writes remain separate: `.tags.txt` for optimized tags and `.txt` for natural-language captions; a caption run may replace its own unreviewed `.txt` only after an accepted response.

Image upload must be explicitly approved per target scope; both modes show the provider and selected image count. Single-item requests do not imply single-request concurrency. This branch has code-level tests for the request shape; real provider integration and native desktop checks require a Rust toolchain.
