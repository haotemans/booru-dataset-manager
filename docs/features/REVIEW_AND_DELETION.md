# Review and deletion

Image-edit confirmation mode (D-136): the shared persistent “编辑后二次确认” switch is available in the review editor and System Settings → Image editing. Default on previews crop/inpainting before a second confirmation. Off changes the buttons to “裁剪并保存” / “去水印并保存”; clicking runs the operation and commits a validated result directly. Drawing masks/crops alone never saves. The mode is captured at click time. Cancel or leaving the image disposes unsubmitted processing results; a background save cancels before durable journal intent, or finishes consistently if intent is already published. Failure retains the error and, if available, a result for inspection/retry. Both modes use the same hash/dimension/format validation and recovery journal. Image dimensions, thumbnails and caches update on success; the selected repair tool remains available for repeated edits. This is the optional exception to the preview-confirm descriptions below. It does not disable deletion or text-output confirmation.

Saving runs off the UI thread: image decoding/encoding, thumbnails, hashes, file promotion and SQLite writes use a worker. Direct-save skips display-preview decoding and upload. Manual preview pixels are also prepared on a worker. “正在保存…” remains visible while the interface responds; closing or switching images retains result tracking until the worker finishes so committed dimensions do not go stale. Saving blocks concurrent processing/deletion until acknowledged. Existing source-format and journal recovery checks remain intact.

Image review and similarity review are separate. Grid and large-image views show source, artist/character, tags, caption and similarity candidates. States: pending, keep, unsatisfactory, needs review; ratings 1–5; quality flags include blurry, low resolution, compression, composition and content mismatch.

The current review workspace occupies the app window with a persistent image canvas and an independent right text/editor panel. Originals load asynchronously on open; Open original launches the current managed image in the system viewer. Wheel zoom follows the pointer, dragging pans, double-click resets to fit, and 100% uses physical screen pixels. Switching images resets the viewport and disposes uncommitted edit previews. Fixed controls and implemented shortcuts: arrows navigate, 1/Delete queue rejection, 2 pending, 3 keep, Space toggles current selection, Ctrl+A selects the frozen review scope. Decision-and-next is enabled by default and can be disabled; failed saves do not advance, and the last decision completes the session through deletion confirmation when needed. Text confirmation is separate from image Keep. Ratings/quality flags, association/tag editing, AI region detection, prompt-based repainting and source re-fetch remain pending.

Original tags are grouped by the source's artist, character, general, copyright and meta fields; unmatched terms remain in Other. Artist and Character appear before General so they remain visible with long general-tag lists. Tokens retain underscores, and Copy returns the exact complete source text. This display starts no optimization or metadata job.

Crop is a third right-panel mode. Drag to draw, drag inside to move, or drag a corner to resize; Free, 1:1, 4:3, 3:4, 3:2, 2:3, 16:9, 9:16 and Original ratio are supported. Selection coordinates remain in current-image pixels during pan/zoom and stay inside the image. Preview is local and requires no model. Confirm replaces the current image under the later unified editor decisions D-065–D-078; no pre-crop image archive is retained. Cancel/switch/close preserves the current file. Current dimensions, hash, thumbnail and visual caches update together; immutable source-post dimensions and text remain separate. Subsequent inpainting/crops and exports use the current dimensions.

Inpainting is integrated into the right panel (D-068–D-072). Select rectangle, brush or polygon, create/refine a mask in source pixel coordinates, then generate a local Anime LaMa/LaMa preview. Right-drag pans while a selection tool is active. Current image / Repair preview supports comparison. Only Confirm replace writes the current managed image; cancel, close and image switching discard previews and leave the current output intact. Installation is a separate explicit download; inference never uploads images or silently switches to an API. [Local model details](../../models/inpainting/README.md).

Commit validates dimensions/format/hash and mask compatibility, retains the source format, saves the current mask/model/settings/source provenance, refreshes the thumbnail and invalidates visual-analysis caches. Crop stores its rectangle and output dimensions without a fabricated mask; a prior inpainting mask is removed after crop commit. A sibling repair journal makes a confirmed replacement recoverable after interruption between image promotion and SQLite metadata commit. Source-post metadata and text artifacts stay unchanged; the source hash remains available even after successive edits. There is one current local output, with no historical image archive. JPEG replacement includes JPEG re-encoding. Remote detection, remote backup and source re-fetch are outside this implementation.

Rejection first queues an image for deletion; it does not immediately remove files or records. D-080–D-083 supersede the original quarantine/recycle proposal: the candidate list and impact preview require explicit confirmation; cancellation preserves the listed images and records, while confirmation immediately deletes the image and its owned data without an undo window or trash. Shared resources must be preserved and failures reported accurately. D-123–D-132 define the later automatic-deduplication exceptions and audit rules.

Deleting an artist/character from its collection list means deleting that record and all canonical media associated with it (D-134). Images have one library identity across views: remove each affected image once, along with its owned text/review/analysis data and all references from other artist/character views. Other artist/character records remain, with updated counts/covers. Do not expand the deletion to those records' unrelated images or the image's entire visual identity group. Editing an association separately is not this delete action; shared tag definitions, models and other images' data survive.

The desktop provides one toolbar delete entry on both Artist and Character lists. Click it to enter selection mode, click cards to select/unselect, then click Delete to review the frozen record IDs AND media IDs, record Tags, affected image thumbnails/filenames and both deletion counts. Cards have no individual trash buttons. Cancel or Escape exits selection mode; cancelling/closing the confirmation returns to the selection without changing records or images. Confirmation removes only the reviewed scope; changed associations require reconfirmation before any mutation. Confirmed deletion exits selection mode and cleans media selections, review/deletion queues, action scope, contexts and pagination. Both collection types and the dashboard derive counts/covers from the remaining unique media, with no hidden orphan images.

## Production cleanup and remaining limits

Production media cleanup is connected through SQLite and a durable deletion journal for originals, sidecars, owned artifacts/analysis and references. Active processing blocks deletion confirmation. If collection record deletion fails after media cleanup, the remaining records and error are retained for retry. Cross-process coordination and a complete partial-failure recovery UI remain pending. Sample cascades remain memory-only. See [workflow delivery](../planning/WORKFLOW_DELIVERY.md) and [collection workflow](COLLECTION_CATALOG.md).
